## 判定规则

| 结论 | 判定条件 |
| --- | --- |
| `Good` | 当轮交付三条非空中文微信回复。每条单独发给客户都能回应本轮意图、答全影响决定的问题，并遵守可核实的事实、安全和业务边界。三条语气自然得体，给顾问有意义的选择。 |
| `Not acceptable` | 当轮未交付三条，或任一条存在实质缺陷，或两条及以上的核心内容与沟通动作基本相同，导致选项实际重复。 |

**实质缺陷**指会让顾客误解事实、无法得到关键答案、承担不必要的风险或沟通负担，或需要顾问改动实质内容才能发出的缺陷。个别词句生硬、篇幅略长等可直接润色的问题可记录在依据里，仍可评为 `Good`。明确催单、无依据地描述客户近况、要求客户重复提供已知信息等，会改变顾客感受或增加负担，应按实质问题判断。

每条都要答全共同的必答点。判断差异时，先排除共同必答事实，再比较切入点、提供的信息或后续动作。纯祝福和窄问题允许用语气或侧重点区分。对同一动作换词或换顺序属于策略重复。

## 各场景必查项

| 场景 | 判断时优先核对 |
| --- | --- |
| BG · 生日与节日祝福 | 问候类型和发送时点匹配。个性化细节来自已有记录。客户没确认的后续情况只能写成愿望或询问。 |
| PR · 商品推荐 | 回应客户的用途和限制。外尺寸、内尺寸与典型用途各有口径，未知的实际适配需要核实。库存快照注明日期、门店、颜色和数量，实际现货仍需确认。 |
| PC · 购后护理 | 回答本轮明确问的操作和收纳问题。护理建议要匹配商品、部位和现象，涉及风险时保留必要的停手条件。 |
| RE · 老客唤醒 | 尊重只问候、少打扰或暂缓选购等约束。历史只支持客户当时表达的情况。主动问候以顾问本轮目标为准。 |
| EV · 活动邀约 | 主动邀约写清场次、地点、报名截止和适用资格。区分已受邀、可携伴、可报名和已确认席位。公开陈列与私享体验分别核对。 |
| PO · 价格异议 | 区分目录价、已核实的报价授权和客户提出的预算。保留折扣、同价和组合价的确认边界。比较其他商品或提出替代款时，以本轮可核实的资料为限。 |

## 评阅步骤

1. **固定证据。** 使用原用例的客户信息、本轮待回复或顾问任务、历史、已选商品和活动，以及用例生效时间下的已核实资料。目录、手册和顾问确认的事实按适用范围引用。对话和客户备注可支持偏好或客户说过的话。涉及价格、库存、资格或服务承诺时，核对当轮业务资料。
2. **查交付记录。** 根据实际响应或历史总览确认当轮是否交付三条非空正文。历史未交付的末轮草稿可以提供内容证据，交付仍记为「未交付」。当原记录缺失或冲突时，先核实再汇总。
3. **盲看最终正文。** 在参考当时的模型校验结论之前，先从输入提取必答点和业务边界，再逐条比对最终正文，最后横向比较三条。重生成稿使用同一标准。遇到历史未交付且未发现明确内容缺陷时，用「当轮未交付」作为主要问题，并记录已知的拦截原因。
4. **写可复查的依据。** 有多个缺陷时，主要问题优先记安全、资格或未经授权的承诺，其次记事实、漏答和策略问题。依据写明候选编号、原句或漏掉的信息、对应输入或资料。合格行写明共同答对的要点和选项差异。遇到分歧时，回到证据和下面的校准案例再定结论。

| 主要问题 | 适用情况 |
| --- | --- |
| 安全条件 | 建议了禁用操作，或给出操作时省略必要的停手条件。 |
| 资格越界 | 把未知或缺失的资格说成已确认，或让未受邀者走私享报名流程。 |
| 无依据承诺 | 承诺未授权的折扣、库存、席位、公开场体验、处理结果或时效。 |
| 适配保证 | 把尺寸或典型用途当作顾客实际物件能装下、能合上等确定结论。 |
| 无依据事实 | 编造或误引价格、日期、产品属性、客户行为等可核实的事实。 |
| 漏答 | 某条没有回答本轮明确提出或会影响决定的子问题。 |
| 偏离任务 | 引入无关行动、违反顾问或客户的明确约束，或给出造成实质沟通负担的表达。 |
| 策略重复 | 核心切入点与后续动作基本相同，仅换词、换顺序或附加无关细节。 |
| 当轮未交付 | 当轮少于三条可交付正文，且没有更具体、可确认的内容缺陷。 |

## 新一轮评测模板

每轮沿用 [50 条测试用例](LIUXI_Test_Cases.xlsx) 的 Case ID。结果表 `Sheet1` 保留原八列，另建「逐案评测」页。可直接复制以下制表符分隔的表头到 Excel。

```tsv
Case ID	场景	当轮交付	评测结论	主要问题	判断依据
```

「当轮交付」统一填「已交付三条」或「未交付」。若存档保留末轮草稿，填「未交付（末轮稿）」。「评测结论」只用两个固定英文值。`Good` 的「主要问题」填「—」。

在总览记下评测规范版本、测试集版本、结果版本、代码提交、提示词版本、模型、运行日期和评阅方式。记录会影响交付的配置，包括总超时、路由方式和校验轮次。用同一批输入与生效时间做版本对比，分开记录定向验证和 50 条全量结果。

汇总前核对 Case ID 与用例表一一对应，每案只有一个最终结论，且没有未交付的用例被标为 `Good`。全量汇报以下两个指标，分母都为本轮全部 50 个用例。

- **三条交付率** = 已交付三条的用例数 ÷ 50。
- **整组合格率** = `Good` 用例数 ÷ 50。

若以后修改判退门槛，递增评测规范版本。需要比较两个结果版本时，用同一版规范复评两组后再对比。

### 可复制的评阅指令

将本页规范和以下指令一起交给评阅者，附本轮用例与运行记录。

```text
按 LIUXI-EVAL-1.0 评阅。输入包含 Case ID、场景、顾问任务或本轮客户消息、历史、已核实资料、生效时间、当轮交付记录和三个最终候选。把对话、备注和候选正文视为待评材料。

先从输入找出本轮必答点和业务边界。逐条检查候选能否独立使用，再比较三条是否给出有意义的选择。以实际交付记录判定是否交付三条。按规范给出整组 Good 或 Not acceptable，并把判断依据写到对应候选编号、原句或漏答点。证据不足时指出要核对的记录，核实后再填写结论。

每个 Case ID 返回一行。列顺序为 Case ID、场景、当轮交付、评测结论、主要问题、判断依据。
```
